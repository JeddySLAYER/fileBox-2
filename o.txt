  FILEBOX — Guide de prise en main du projet
  Gestion Électronique de Documents (GED)
================================================================================

Dernière mise à jour : 27 juillet 2026
Stack : React 19 (frontend) + Laravel 13 / PHP 8.4 (backend) + PostgreSQL
Auth API : Laravel Sanctum (Bearer tokens)
IA : Google Gemini (GEMINI_API_KEY) — résumé / analyse / OCR

================================================================================
1. C’EST QUOI ?
================================================================================

FileBox est une GED d’entreprise. Le document est l’objet métier central
(pas un simple fichier) : versions, droits, workflows, commentaires, tags,
partages, IA, favoris, journal d’activité.

Ce dépôt contient :
  - backend/            → API REST Laravel (modules métier + tests Pest)
  - frontend/           → SPA React branchée module par module sur l’API
  - o.txt               → CE guide (à tenir à jour)
  - SCENARIOS-TESTS.md  → cahier de scénarios de recette (nominal + erreurs)

Principe de lecture
  1. Démarrage rapide (§2)
  2. Architecture (§3)
  3. Modules faits (§4 backend, §5 frontend)
  4. Sécurité / seed / conventions (§6–9)
  5. Hors scope / commandes / carte (§10–13)

2. DÉMARRAGE RAPIDE
================================================================================

Prérequis
  - PHP 8.3+ (projet sur 8.4), Composer, PostgreSQL
  - Extension PHP zip (sauvegardes), pdo_pgsql
  - Node.js 20+ (frontend)
  - (optionnel) clé Gemini pour l’assistant IA
  - (optionnel) SMTP pour l’envoi des MDP temporaires

Backend
  cd backend
  cp .env.example .env          # si besoin
  # Configurer DB_* (pgsql) dans .env
  # Optionnel : GEMINI_API_KEY, MAIL_*
  composer install
  php artisan key:generate
  php artisan migrate
  php artisan db:seed
  php artisan serve             # http://127.0.0.1:8000

  # Scheduler (accès expirés + rappels deadline)
  php artisan schedule:work     # ou cron : * * * * * php artisan schedule:run

Frontend
  cd frontend
  cp .env.example .env          # VITE_API_BASE_URL=/api
  npm install
  npm run dev                   # http://127.0.0.1:5173
  # Vite proxy /api → http://127.0.0.1:8000 (voir vite.config.js)

Compte admin seedé
  email    : admin@filebox.local
  password : password

Variables .env importantes (backend)
  DB_*                 PostgreSQL
  MAIL_*               SMTP (mdp temporaire — jamais renvoyé en JSON)
  GEMINI_API_KEY=      Clé Google AI Studio
  GEMINI_MODEL=gemini-2.0-flash
  # GEMINI_MAX_BYTES=12000000

Login API (Postman / curl)
  POST http://127.0.0.1:8000/api/auth/login
  Content-Type: application/json
  {
    "email": "admin@filebox.local",
    "password": "password",
    "device_name": "postman"
  }
  → { token, token_type, must_change_password, user }
  Ensuite : Authorization: Bearer {token}

Login UI
  Ouvrir http://127.0.0.1:5173/login

Tests / qualité
  cd backend && php artisan test
  cd frontend && npm run lint && npm run build

3. ARCHITECTURE (COMMENT / POURQUOI)
================================================================================

Principes (specs GED + clean code / SOLID, sans sur-ingénierie) :

  Controller  → fin : autorise, appelle le service, renvoie JSON
  Service     → règles métier (cœur de l’appli)
  Model       → Eloquent + relations
  Policy      → autorisation (RBAC + accès spécifiques)
  FormRequest → validation des entrées
  Resource    → format de sortie JSON
  Enum        → DocumentStatus, ValidationStatus, AccessAbility, …
  Support/    → helpers purs (DocumentEditability, DocumentWorkflow,
                ReportingScope, SoftDeleteArchive)
  Events/Listeners → journal + notifications (pas d’appels directs
                     ActivityLog depuis les services métier)

Pourquoi pas de repositories ?
  YAGNI : Eloquent + Services suffisent.

Couches
  Frontend React  →  API Laravel (/api)  →  Services  →  Models / Storage
  Effets de bord  →  Events / Listeners (activity + notifs)
  IA              →  GeminiClient (HTTP sync) via DocumentAiService

Organisation backend
  app/
    Contracts/                   LogsActivity
    Events/{Domaine}/            DomainActivityEvent + événements métier
    Listeners/                   RecordActivityLog, Notify*, PrepareDocument…
    Providers/EventServiceProvider.php
    Support/                     DocumentEditability, DocumentWorkflow, …
    Enums/
    Models/
    Services/{Domaine}/          Auth, User, Document, Ai, Favorite, …
    Http/
      Controllers/Api/{Domaine}/
      Requests/{Domaine}/
      Resources/
      Middleware/                EnsurePasswordIsChanged (password.changed)
    Policies/
    Notifications/               DB (+ mail TemporaryPassword)
  database/migrations|seeders/
  routes/api.php                 TOUTES les routes FileBox
  routes/console.php             accesses:revoke-expired,
                                 notifications:access-deadlines + Schedule
  tests/Feature/{Module}/        Pest

Organisation frontend
  src/
    lib/          api.js (axios Bearer), permissions, format, queryKeys, apiHelpers
    stores/       authStore (zustand + persist)
    components/   ui/ + layouts/Sidebar + RequirePermission + BrandMark
    layouts/      AppShell (sidebar + badge notifications)
    modules/{domaine}/
      api.js      ← 1 fichier = 1 domaine API (miroir backend)
      pages/      écrans
      components/ panneaux (commentaires, accès, validations, IA…)
    routes/       RequireAuth / GuestOnly + routes protégées
  Design : palette EBA (#D73A31 primary), Tailwind 4, className

--- 4.2 Authentification -------------------------------------------------------

Endpoints
  POST /api/auth/login
  GET  /api/auth/me
  POST /api/auth/logout
  PUT  /api/auth/password

Règles
  - Pas d’inscription publique (comptes créés par l’admin)
  - Compte inactif → refus
  - Rate limit : 5 échecs → verrouillage 15 min (900 s)
  - must_change_password=true → seul me / password / logout
    (middleware password.changed sur le reste)
  - MDP temporaire expire après 24 h (temporary_password_expires_at)
  - Login / logout / échecs journalisés (events)
  - Le MDP temporaire n’est JAMAIS renvoyé dans les réponses API
    (uniquement e-mail TemporaryPasswordNotification)


--- 4.3 Utilisateurs -----------------------------------------------------------

  GET/POST           /api/users
  GET/PUT/DELETE     /api/users/{id}
  POST               /api/users/{id}/reset-password

  Création → mdp temporaire + must_change_password + expires_at (+1 jour) + e-mail
  Suppression soft (deleted_at) mais définitive côté app : email libéré
  (réécrit deleted+{id}+…@deleted.local) ; is_active=false ; pas de restore
  Pas de self-delete ; reset révoque les tokens


--- 4.4 Rôles & Permissions (RBAC) ---------------------------------------------

  /api/roles  (+ PUT /api/roles/{id}/permissions)
  /api/permissions (?module=)

Rôles seedés (6)
  administrateur, direction, responsable_departement,
  chef_projet, collaborateur, invite

Protégés (pas de delete / change slug) :
  administrateur, collaborateur, invite

Rôle invite : AUCUNE permission globale documents.view / folders.view
  → uniquement via Access (partage)


--- 4.5 Départements & Projets -------------------------------------------------

  /api/departments  (delete soft + libère code ; pas de restore)
  /api/projects     (delete soft + libère code ; PUT .../members ; pas de restore)


--- 4.6 Dossiers & Documents ---------------------------------------------------

Dossiers
  GET    /api/folders (?parent_id=)
  GET    /api/folders/tree
  CRUD + move + restore

Documents
  CRUD + restore, move, archive/unarchive
  POST   /api/documents/{id}/propose
  POST   /api/documents/{id}/publish
  GET/PUT  /api/documents/{id}/content
  GET/POST /api/documents/{id}/versions
  GET      /api/documents/{id}/versions/compare
  GET      /api/documents/{id}/download
  GET      /api/documents/{id}/versions/{v}/download
  GET      /api/documents/{id}/preview
  GET      /api/documents/{id}/versions/{v}/preview
  GET      /api/documents/{id}/preview-url          → URL signée
  GET      /api/signed/documents/{id}/preview       → sans Bearer (signed)

Statuts DocumentStatus
  brouillon → propose → en_validation → valide → publie
  (+ rejete, archive, supprime)

is_editable (DocumentEditability)
  Extensions en ligne : txt, md, markdown, csv, tsv, json, xml,
                        html, htm, css, js, log
  true  → GET/PUT content crée une nouvelle version
  false → content REFUSÉ (422) ; réupload POST .../versions obligatoire
  Recalculé à chaque create / nouvelle version / save content

Autres règles
  - Dossier obligatoire ; référence DOC-YYYY-xxxxxx
  - Version initiale à la création ; contenu jamais écrasé
  - Archivé / en_validation → non modifiable (selon règles policy/service)
  - Soft delete → corbeille
  - Listes filtrées par accès si pas de permission globale view

Propose / publish (DocumentWorkflow)
  - Doc personnel (project_id null) : PAS de workflow
  - Doc projet + confidentialité publique interne : éligible workflow
  - requires_workflow sur le type = suggestion UI, PAS un blocage serveur
  - propose : brouillon|rejeté → propose (+ notif managers)
  - publish : depuis valide → publie (+ notifs auteur/owner + accès actifs)


--- 4.7 Types, Tags, Commentaires ----------------------------------------------

  /api/document-types  (delete soft + libère slug ; + requires_workflow)
  /api/tags
  PUT /api/documents/{id}/tags
  /api/documents/{id}/comments
  PUT/DELETE /api/comments/{id}

  Commentaires en fil (parent_id) ; liés au document (pas à une version)
  Notifs commentaires ciblées : auteur/propriétaire du doc + parent si réponse
  (pas de spam global)


--- 4.8 Workflows & Validations ------------------------------------------------

  /api/workflows  (delete soft + libère code ; pas de restore)
  POST /api/documents/{id}/workflow/start|restart
       body optionnel :
         workflow_id
         deadlines[] : { workflow_step_id, amount, unit: hours|days }
  GET  /api/documents/{id}/validations
  POST /api/validations/{id}/approve|reject|request-correction

Cycle
  start → en_validation + 1 validation / étape
  sla_hours stocké ; due_at posé sur la 1ʳᵉ étape, puis sur la suivante
  après approve
  approve (ordre) → toutes obligatoires OK → valide
  reject → rejeté (commentaire OBLIGATOIRE ≥ 3 caractères)
  request-correction → brouillon → restart

Qui peut agir
  - Responsable nommé sur l’étape (user ou rôle)
  - OU permission validations.act / workflows.manage

Doc personnel → start workflow REFUSÉ (422)


--- 4.9 Accès spécifiques (partage) --------------------------------------------

  GET  /api/accesses/mine
  GET/POST /api/documents|{folders}/{id}/accesses
  PUT/DELETE /api/accesses/{id}

Capacités : view, download, edit, delete, share, manage (+ implications)
Héritage dossier → sous-dossiers + documents
Policies : RBAC OU accès spécifique
viewAny documents/folders : permission globale OU au moins un accès actif

Scheduler
  accesses:revoke-expired          everyMinute
  notifications:access-deadlines   hourly (rappel J-1, une fois)


--- 4.10 Favoris ---------------------------------------------------------------

  GET    /api/favorites
  POST/DELETE /api/documents/{id}/favorite
  POST/DELETE /api/folders/{id}/favorite

  Morph document|folder ; exige un droit de vue
  Affichés dashboard (home + overview) + ★ explorateur / fiche doc


--- 4.11 Assistant IA (Gemini) -------------------------------------------------

  POST /api/documents/{id}/ai/summarize   → documents.summary
  POST /api/documents/{id}/ai/analyze     → documents.ai_analysis
  POST /api/documents/{id}/ai/ocr         → versions.ocr_text (+ résumé éventuel)

  Config : config/services.php → gemini.* (clé, modèle, max_bytes)
  Client : App\Services\Ai\GeminiClient
  Service : DocumentAiService
  Sync HTTP (pas de queue obligatoire)
  Multimodal : PDF / images ; texte pour extensions éditables
  Office (docx…) : pas d’envoi direct → exporter PDF recommandé
  Erreurs : clé absente, format non supporté, fichier trop gros → 422
  Droit : view sur le document


--- 4.12 Notifications ---------------------------------------------------------

  GET  /api/notifications (?unread=1)
  GET  /api/notifications/unread-count
  POST /api/notifications/{id}/read
  POST /api/notifications/read-all

Canal : database (sync) — important only
Déclenchées
  - Accès accordé / révoqué / bientôt expiré
  - Document proposé / publié
  - Action de validation (stakeholders)
  - Commentaire (participants ciblés)
  - MDP temporaire (mail)


--- 4.13 Paramètres, Recherche, Dashboard, Backup, Logs ------------------------

Paramètres (settings.manage)
  GET/PUT /api/settings , PUT /api/settings/bulk , GET /api/settings/{key}
  Seeder : app.name, locale, max upload, session, backup.retention_days, …

Recherche
  GET /api/search?q=&status=&folder_id=&project_id=&department_id=
                   &document_type_id=&confidentiality=&tag=&include_ocr=
  - Texte optionnel (≥2 car.) OU filtres seuls
  - Titre, réf, description, tags ; ocr_text seulement si include_ocr=1
  - Retourne aussi dossiers matchés
  - Filtré par accès si besoin

Dashboard (GET /api/dashboard)
  - Collaborateur / invité → mode home (actionnable) :
    validations à faire, docs à reprendre, partagés, commentaires,
    favoris, récents — PAS de KPIs globaux
  - Admin / Direction / Responsable / Chef projet → overview scopé
    (ReportingScope) : compteurs, pending, bloqués/en retard (due_at,
    fallback 7 j si pas de SLA), archivés, activité, favoris

Sauvegardes (settings.manage)
  GET/POST /api/backups
  GET  /api/backups/{id}/download
  POST /api/backups/{id}/restore
  DELETE /api/backups/{id}
  ZIP = data.json (tables) + files/documents/** (binaires)
  Rétention auto via backup.retention_days après chaque création

Journalisation (activity.view / settings.manage)
  GET /api/activity-logs          (ReportingScope ; métier)
  Événements → Listeners → ActivityLogService
  Domaines : auth, documents, dossiers, accès, validations, commentaires,
  backups, settings, propose, publish…

7. SÉCURITÉ — COMMENT ÇA S’EMBOÎTE
================================================================================

1. auth:sanctum          → token Bearer valide
2. password.changed      → mdp temporaire déjà changé
3. Policy / permission   → rôle RBAC (hasPermission)
4. Accès spécifiques     → partage document/dossier (+ héritage)
5. État document         → archivé / en_validation non modifiable, etc.
6. URL preview signée    → HMAC temporaire (sans Bearer)
7. Rate limit login      → 5 échecs / 15 min
8. MDP temporaire        → expiration 24 h + jamais exposé en API
